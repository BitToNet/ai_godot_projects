## 目标

|- **目标口径已定（决策 9）：1080p60**（1920×1080 / 稳定 60 FPS ⇒ 帧预算 ≤16.6 ms）。
- T1-14 只**测量**；本任务把结果变成**可判失败的指标**（E4：性能达标）。
- 没有这条，性能会随内容一起劣化到发布前才发现。

## 实现要点

1. 把测法固化成可重复流程（与 T1-14 同一套机位与场景清单）。
|2. 设帧预算并按场景分级（大地图远景 / 近景 / 战斗 / 会战 / 菜单），**总预算 = 16.6 ms @1080p60**。
3. 指标进 `perf_baseline.json` 并**进门禁**（或 nightly，视耗时）。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

|- [ ] **A1** 设计稿先写进本卡（场景清单 + 每类帧预算 + 容差，总预算按 **1080p60 / ≤16.6 ms** 分配）并复核。
- [ ] **A2** 断言：所有场景达标；人为把植被密度或视距调高后必须**报红**。
- [ ] **A3** 既有 headless 软指标（`veg_instances` / `nodes`）与实时指标**分开存放**，不再混用。
- [ ] **A4** 门禁全绿。

## 回退

- 若实时帧率无法在 CI 上稳定测量，改为「本地必跑 + 发布前人工记录」并在本卡写明这不是自动守护。
