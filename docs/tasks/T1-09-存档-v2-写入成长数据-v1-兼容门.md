## 目标

- ⑤⑥ 一旦落地，存档就必须携带 Hero / 装备 / 物品栏 —— 否则「变强」一读档就没了。
- 但**老档不能变砖**：v1 存档必须仍然读得进来。

## 实现要点

1. 沿用既有三道身份门（版本 / magic / 种子 + 实体 id），新增 `version=2` 分支。
2. 读 v1 时**补出默认 Hero**（不装装备、等级 1），而不是拒绝加载。
3. 往返稳定性：v2 存 → 读 → 再存，字节级稳定（既有 `save_check` 已在测这条）。
4. 坏数据钳制：缺失 / 越界 / 类型错的成长字段要落到合法默认值，不许崩。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

- [ ] **A1** `save_check` 断言：v2 往返稳定、版本门拒绝「未来版本」、**v1 样本档能读且补出默认 Hero**、坏数据被钳制。
- [ ] **A2** `tools/fixtures/save_v1.json` 是**真实 v1 产物**（不是手写），提交入库作为回归样本。
- [ ] **A3** 门禁全绿，项数不减少。
- [ ] **A4** 生成指纹与统计一字不变。

## 回退

- 若 v1 → v2 自动迁移太复杂，退化为「读出 v1 后提示另存为 v2」，但**加载 v1 绝不许崩**。
