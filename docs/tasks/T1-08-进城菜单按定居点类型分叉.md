## 目标

- 现在进城菜单对所有定居点基本同形；要按 kind 分叉：**村庄 / 城镇 / 城堡**各有一套服务。
- 这是 ⑥「菜单」那一半的收口，也是把 ⑤⑥ 与既有经济闭环接起来的地方。

## 实现要点

1. 菜单项表**按 kind 生成**，每项带可用条件与「灰掉原因」。
2. 村庄（招募 / 补给 / 长老）/ 城镇（市场 / 酒馆 / 铁匠 / 招募）/ 城堡（管家 / 军需）—— 具体条目在开工时定，参考已落档的原始怪癖记录（§10.x）。
3. **既有 4c 断言必须继续通过**（城镇交互定式）；若因分叉必须改它，要**显式更新并写明原因**，不许删断言。
4. 菜单尽量做成**表驱动**而不是 if 链，便于断言「三类 kind 的条目集合」。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

- [ ] **A1** `town_menu_check` 扩展断言：三类 kind 的菜单项集合、每项可用条件、灰掉原因。
- [ ] **A2** 原有 4c 断言仍绿；若更新过，提交信息与 `docs/PLAN.md` §D 要写明改了哪几条、为什么。
- [ ] **A3** `i18n_check` PASS 且 `ui_total` 仍为 **0**。
- [ ] **A4** 门禁全绿；指纹与统计一字不变。
