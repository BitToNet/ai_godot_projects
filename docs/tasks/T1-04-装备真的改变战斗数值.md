## 目标

- 装备不能只是面板上的数字 —— 必须**真的**改变战斗里的伤害 / 减伤 / HP / 速度。
- 这是「变强」闭环能不能立住的关键一环：没有它，⑤ 只是加了个显示面板。

## 实现要点

1. 找出战斗里**当前硬编码**的玩家属性来源（`PlayerFighter` / `BattleScene`），改为从 `Hero.stats()` 读。
2. 装备修正走**独立乘区**（基础 × 装备加成），**不许改 AI 平衡公式** —— §E.9 R6：已校准的 AI 平衡基线不能被破坏。
3. 默认（不装装备）必须与今天**逐位一致**，用断言钉住。
4. 战斗结算台账（`encounter_check` 已有的那套）要能看出装备带来的差异。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

- [ ] **A1** `character_check` 断言：换装前后玩家攻击 / 防御 / 最大 HP / 速度**必须不同**，且**默认装 == 旧硬编码值**（逐字段相等）。
- [ ] **A2** 一场脚本化 Boss 战（`sfx_battle_check` 同款跑法）默认装下的**伤害台账与今天逐位一致**；装上指定装备后必须**不同**。
- [ ] **A3** `encounter_check` / `economy_check` / `scale_probe` 全绿（AI 平衡与规模基线未被破坏）。
- [ ] **A4** 门禁全绿；指纹与统计一字不变。

## 回退

- 若「逐位一致」因浮点求和顺序无法达成，改为**容差断言**（±1e-6）并在本卡写明确切原因 —— **不许悄悄放宽**。
