## 目标

- 现状：`PartyModelBuilder` **没有 `AnimationPlayer`、没有动画、没有武器插槽**（已实测）—— 部队是静态块。
- 商业级大地图上「部队在动、手里有武器」是基本观感要求。

## 实现要点

1. **先定模型来源**：现有马匹 / 骑手是程序化几何 ⇒ 要么程序化绑定 + 简单骨骼，要么换真模型（涉及外部资产与许可，需先定）。
2. `WeaponSocket`：把武器挂到骑手手上（`BoneAttachment3D` 或程序化偏移矩阵）。
3. 动画至少三态：idle / move / attack；用 `AnimationPlayer` 或程序化骨骼驱动。
4. 本任务先把**单实例**跑通，批量装配与 LOD 留给 T1-17。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

- [ ] **A1** 人工核查：部队有可见的移动 / 攻击动作，武器在手上**不飘、不脱手、不穿模**（四个机位都看过）。
- [ ] **A2** 帧率不因动画明显下降（对齐 T1-14 同机位数字）。
- [ ] **A3** 门禁全绿；生成指纹与统计一字不变。
- [ ] **A4** 若引入新资产：`ATTRIBUTION.md` 与许可文件齐备。

## 回退

- 若换真模型成本过高，先做**程序化绑定 + 简单骨骼动画**，并在本卡写明与商业级观感的差距。
