## 目标

- 动作已在 `InputMap` 里（**31 个**），但玩家不能改键。
- E5 要求设置齐全；重映射也是手柄支持的前提。

## 实现要点

1. 列出全部 31 个动作，允许改键 / 恢复默认；冲突要检测并提示。
2. 覆盖要**落盘**并在启动时应用（注意 `InputMap` 是引擎级状态，需在合适时机写入）。
3. 界面上的键位文字本来就该从 `InputMap` 现读（T1-05 已立此约定）⇒ 改键后**所有界面自动同步**。

## 验收标准

> 每条都要能**执行**并给出通过 / 不通过。无法机器判定的，写进「人工核查」并写清看什么。

- [ ] **A1** 设计稿先写进本卡（动作清单来源 + 冲突策略 + 落盘格式 + 应用时机）并复核。
- [ ] **A2** 断言：改键后该动作的键盘 / 手柄事件确实生效；冲突被拒绝且有提示；恢复默认可用。
- [ ] **A3** 断言：改键后既有 4b 输入定式仍绿（分发与让路没被破坏）。
- [ ] **A4** 门禁全绿；`ui_total` 仍为 0。

## 回退

- 若引擎级 `InputMap` 写入时机有问题，改为「启动时应用 + 运行中即时应用」两段处理并记明。
