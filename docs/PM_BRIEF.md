## 0. 一页纸结论

| 项 | 结论 |
|---|---|
| 产品是什么 | 《骑马与砍杀》风格的 **3D 程序化生成战略大地图** + 《神之天平》风格的 **2D 横版 Boss 战斗**，Godot 4.7 / GDScript，单机 |
| 当前阶段 | **可玩垂直切片（pre-alpha）**，版本 `0.6.0`。核心循环「打 → 赚 → 经营 → 再打」已跑通，**缺"变强"那一环** |
| 质量状态 | **一键门禁 29 项全绿，用时 60.4 s，零 ERROR**（2026-10-15 本机实测，见 §3） |
| 确定性 | 生成指纹 `958433c2f04c0e39…` 与基线**逐字节一致**；世界内容 18 定居点 / 7 桥 / 5150 植被与基线一致 |
| 规模 | 110 个 `.gd` / **23 393 行** + 6 个 shader / 587 行；默认世界 **4096 m**、**100 支部队** |
| 近三天节奏 | 10-12 ~ 10-14：**8 个轮次 + 17 个批次、60+ 次提交**，每批都以「跑满门禁 + 提交推送」收尾 |
| 我的判断 | 底座（确定性、性能、自检）**已经稳到可以放心加内容**。下一步的瓶颈不是技术，是**玩法深度与内容量**，以及**一次"实机帧率"体检** |
| 最近一个里程碑 | **M1 / v0.7**：资产补齐收口（城镇城堡真模型 + 玩家成长 + 商店），目标 **10-28** |

**需要老板拍板的 5 件事**见 §7 —— 其中第 1（目标交付节点）与第 4（玩法纵深 vs 资产观感谁优先）会直接改写 §6 的排期。

## 1. 当前功能清单（用户视角，共 11 个模块）

### 1.1 世界与地形
| 能力 | 关键实测 |
|---|---|
| 全程序化地形：大陆衰减 + 山脉脊状噪声 + 丘陵 FBM + 沙丘 + 细节噪声 | 默认 `map_size = 4096 m`，最大高度 ≈ 170 m，海平面 0 |
| **单一 `map_seed` 决定整张地图**，换种子得到"完全不同但同样合理"的世界 | 种子 `20250929` |
| 生物群系（沙漠/湿度/岩石/森林）、北部雪山、中部草原、东部沙丘、海岸线 | 4 类掩码供地形/定居点/植被共用 |
| 河流与渡口：2 条河（强制单调下降河床 + 只下切不填高）、每条河 2 处浅滩 | 7 座木桥自动选位生成 |
| 湖泊 / 海洋 / 河流水面：顶点波 + 菲涅尔 + 水深混色 + 岸边泡沫 | 海洋 3200×3200 平面遮住地图切边 |
| 地形 7 种材质按高度 + 坡度 + 噪声混合（沙/草/干草/土/岩/雪/道路） | 4 级 LOD（32/16/8/4 段）+ 裙边遮缝 |
| 植被 5150 实例：针叶/阔叶/仙人掌/枯树/岩石，按 256 m 分块 MultiMesh | 排除水面/河流/道路/渡口/桥面/坡度>0.46/定居点内 |

### 1.2 战略大地图与操作
| 能力 | 关键实测 |
|---|---|
| 骑砍式相机：跟随 + 缩放（高度 20→400）+ 俯角联动（26°~72°）+ 拖拽旋转 + 边缘平移 | 拉到最远自动进**战略视图**（植被整块剔除、标签放大） |
| **骑砍式时间流动**：行军途中世界时间自动流动；抵达瞬间暂停；长按空格原地推进；行军途中按空格中断 | 流速 ×1 / ×2 / ×4；1 游戏日 = 120 秒真实时间 |
| 点击地面 A* 寻路 + 目标点标记 + 贴地路径预览线 | 速度分级：道路 ×1.2 / 草 ×1.0 / 林 ×0.7 / 山 ×0.5 / 雪 ×0.4 |
| 点单位交互（第七轮 ①）：点击拾取部队/定居点 → 选中面板 → 再点同一座城 = 进城 | 屏幕空间拾取半径 14~90 px，小目标让先 6 px |
| 悬停提示、键位说明、FPS/draw call 面板、开场 Loading 遮罩 | 键位全部走 `InputMap`（29 个动作，含手柄） |

## 2. 可玩闭环盘点（这张图决定下一步优先级）

```
        ┌─────────────┐
        │  打（Boss）  │  ✅ 三类头目 / 三段连招 / 弹反 / 二阶段
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │  赚（战利品）│  ✅ 战利品入账 + 钱袋
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ 经营（城镇） │  ✅ 补给 / 招募 / 贸易 / 驻军 + 军费士气闭环
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ 变强（成长） │  ❌ **缺这一环**：无等级 / 无装备 / 无技能 / 无商店
        └──────┬──────┘
               ▼
          打更强的（❌ 势力不会变强：AI 之间零互动、无外交战争）
```

**结论**：现在是"能打、能赚、能经营、能存档"的四段闭环，**缺口正好是激励链的两端**——
玩家变强（⑤⑥）与对手变强（势力战争）。这两件事做完，"再打一次"才有理由。这是 §5 排期的依据。

```
生成指纹 A/B 一致 + 与存档基线一致 … 958433c2f04c0e39…
hud / input / economy / path_queue / log / i18n / selection / visual / asset /
settlement / encounter / save / audio / perf / scale / map_size /
sfx_battle / sfx_map / bgm / sfx_pcm / audio_cache / sfx_foley / main_scene_900

```
> 只在性能基准上出现 1 条 WARN（未超容差，不判失败）——这是本机耗时漂移的正常表现。

| 风险 | 影响 | 现状与缓解 |
|---|---|---|
| **100 支部队实机帧率未测** | 高：AI 感知是 O(n²) 量级，可能卡 | 已知欠账（ROADMAP §16.9）；**建议列为 ③-3 的第 0 步先量** |
| **村庄真模型帧率未测** | 中：72 个 `MeshInstance3D`，最坏要改 MultiMesh | ③-3 决策点；改法只动一个函数，落位判据不用改 |
| SSAO / glow / 云 GPU 开销未测 | 中：看云时角标 ≈15 FPS | 云是逐像素 5 倍频 fbm，真优化就降倍频，**改动小** |
| 城镇/城堡仍是程序化几何 | 中：③-2 之后村庄是真模型，**风格不统一肉眼可见** | ③-3 解决，已排期 |
| ④ 动作绑定（100 支部队 × 骨骼动画） | 高：无 LOD 会崩性能基线 | 排期已含 LOD 与分帧装配；若不达标则回退为"近处骨骼、远处静态" |
| ⑤ 会碰已校准的 AI 平衡 | 中 | 经济/遭遇已有定式兜底，改坏会红 |
| ⑥ 存档 v2 必须兼容 v1 | 中 | 存档已有版本门与定式自检 |
| 外部素材授权 | 中：BGM 母带与需求方录音的**公开分发权利未确认** | 见 §7 决策 5；对外发布前必须闭环 |

**文档债（不影响功能，但会误导决策）**：`README.md` §五.15 仍写"没有存档/读档"，实际 F5/F9 已交付；
`docs/HANDOFF.md` 是第三轮旧快照，已过期；`perf_baseline.json` 的 `veg_instances` / `nodes` 是旧值（软指标）。
建议在 M1 收口时顺手回填。

## 4. 已明确的观感欠账（非阻塞，但玩家看得见）

1. **农场色块是"平白亮片"**：正午像贴在地上的白纸，夜里不跟着天黑（真模型旁边非常显眼）。
2. 真模型是不透明几何，**村里那点"窗洞透光"的夜灯效果没了**。
3. 4 个 GLB 各自内嵌**同一张** 1024² 图集，引擎按 4 份上传 ≈5.3 MB（实际 1 份就够）。
4. 默认视角（俯角 55°）**看不到天空**，云只在压平视角时直接可见——天空靠环境光与雾色间接起作用。

## 8. 我作为 PM 的三条建议

1. **不要砍掉门禁。** 29 项 / 60 秒的门禁 + 4 个基线，是这个项目最近三天能以极高速度改动却**没有一次"改坏世界"**的唯一原因。它同时是"优化真的变快了"的量尺和"重构有没有偷偷改变世界"的看守。
2. **优先补"成长"，而不是优先加特效。** 现在玩家打赢一场 Boss 战，除了兵力数字变化没有长期收益——这是留存的最大漏洞（决策 4）。
3. **把"实机帧率"当作 M1 的硬门槛。** 100 支部队 + 真模型的实时帧率至今没测过；它是 ④ 能否按计划推进的前提，而不是收尾时的惊喜。
